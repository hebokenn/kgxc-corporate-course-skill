# 5.9.1 验证范围

本版把文字阅读、对象动作与后续信息保留分别编排，加入导出前检查和同一生产渲染器的逐帧检查。结果只证明实现及技术拦截，不能证明学员理解、正常速度听感或用户认可。

## 可重现行为验证

`test_reading_pacing.py` 的25项测试覆盖真实编辑文案、父容器运动与透明度、逐字/遮罩/数字变化、连续阅读窗口、剪切、真实静帧停留、旧结果保留、竞争焦点、常驻标签、局部导出、显式旧课启用及防删策略。实际 Chromium 集成用同一个 `CourseRenderer`、字体、动作库和生产画布检查文字回执及最终字幕层，未用文字标注或动作次数代替阅读曝光。

独立验证先使用合法合成工程寻找误判，再保留同一输入复测，七类发现均修复：

| 场景 | 修复后的判定 |
| --- | --- |
| 标签出框，或在后续被盖住 | 不能用“常驻标签”登记绕过实际可见性检查 |
| 父容器遮罩尚未完成 | 子文字不计作完整阅读；父级真实裁切继续传递 |
| count-up / odometer 尚未显示完整终值 | 变化时间不计作完整正文；计数器按实际格式回传文字 |
| 样段只截取后续回看阶段 | 仍检查应保留的信息，不凭早期读图窗口不相交跳过 |
| 半透明黄色标记层 | 不把10%透明标记误当完全不透明遮盖 |
| 多个兄弟文字各自透明度合格 | 透明度按各自祖先路径相乘，不跨兄弟节点连乘 |
| 最终字幕压住正文 | 外层字幕绘制后也参与阅读遮挡判断 |

17个原有正反案例，以及5个数字终值完成/未完成对照，均得到预期结果。输入通过工作台结构校验，浏览器没有页面错误；每轮被测源码哈希前后一致。证据保留输入、逐帧回执、关键帧及修复前后对照；这些不是实际学员测试。

全量 Skill 回归254项通过；之后新增一项分镜阅读契约反例，所在13项分镜套件再次通过。该反例验证第三种备选也不能漏掉阅读设计，短于当前文字估算下限会被拒绝，无新增正文时须说明图像理解方式，新课不能删除分镜契约。安装器7项、README与打包门槛14项另行通过。

## 现有课程的隔离验证

对本地既有三段小样做只读诊断，发现六处正文稳定停留不足，包括小结、提示、任务、分人与反馈；旧稿、原片和有效确认未改写。

另取其中一个完整流程段及相同原配音，在私有QA目录重排信息：正文逐组出现一次并留在原位，动作与阅读分开安排，在需要核对和全局回看处加入真实静帧停留。实际导出605帧、20.166667秒、1920×1080，完整解码、对象状态/编码像素、动作及阅读检查通过；四组连续稳定曝光分别为18.3、15.067、11.2、6.5秒，均覆盖各自预算，并且没有丢失应保留的内容。较早的信息持续存在不等于同时要求学员阅读四组，新组按顺序进入。

反例保留相同合法时间计划，等动作完成后才遮盖最后一组正文。导出前结构与时间检查通过，但实际渲染阅读检查发现连续停稳仅1.17秒、缺失75帧应保留的信息，停止交付登记；候选与失败证据仍保留。由此区分“计划写得合格”和“实际画面合格”。

课程原件、声音、QA画面与视频不进入公共源码或安装包。该QA导出是验证夹具，没有登记为替代小样、正式课程、首次观看学习验收或用户批准。

## 安装与适用边界

版本、包清单、ZIP CRC、隔离安装与重复安装、项目/Codex/WorkBuddy副本、线上源码/主页和公共安装包完整字节哈希按[发布流程](RELEASING.md)分别核对。WorkBuddy安装副本与原生宿主制课验收分开；本次未验证WorkBuddy原生宿主的新流程。

工程估算是排除明显不足的下限，不是普遍阅读速度或理解达标线。裁切、已知不透明矩形、字幕和文字重叠有实际检查，透明图片、复杂形状、对比度及语义难度仍需正常速度首次观看。自定义引擎须实现真实文字回执；没有回执不能导出。新Skill不会自动重做旧课或补写“通过”。
