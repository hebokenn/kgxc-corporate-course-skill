# 可选关系图与有价值原图 · v3.0

适用：制度/SOP中的流程、交接、层级、条件、字段关联，以及含表单、票据、实拍或操作截图的课程。采用地图或处理来源图片时读取本参考。目标是让学员同时知道“现在看哪里”和“它与其他部分是什么关系”。

流程、多角色协作和泳道内容优先考虑关系地图或泳道图；它们仍是可选方法，实际按内容和讲解效果决定。

## 按关系选图

| 内容关系 | 优先表达 | 必须看得见 |
|---|---|---|
| 操作先后 | 流程图 | 起止、前置条件、箭头方向、结果 |
| 多角色协作 | 泳道图 | 谁负责、跨道交接物、交接条件；一道内动作顺序 |
| 父子、组成、包含 | 树图/关系图、嵌套容器 | 父级、子项、归属边界；不画成时间顺序 |
| 条件与例外 | 分支流程/决策图 | 条件文字、成立/不成立路径、回路与终点 |
| 系统与字段联系 | 原型图/界面连线图 | 真实页面或字段位置、映射/输入输出关系 |
| 实际操作示范 | 原图/原型局部演示 | 所处流程节点、操作位置、操作后的反馈 |

v2.7：本参考仅在选用关系地图时适用。地图可覆盖一个业务单元或整课；按内容和观感选择，不能强制整课同一世界、固定坐标或唯一连续镜头。需要认路时保持对象身份和局部关系；日历、真实操作、实物演示等可独立构图，不为符合地图契约虚构节点和连线。

## 从总览到局部再归回

1. 先给结构全貌：角色/阶段/关键节点与有语义的连线，同时简要讲清主路径。不能先空白再把孤立知识点依次飞入，直到结尾才让观众猜结构。
2. 共用稳定的地图ID、节点ID和世界坐标。当前区域放大时同时保留真实相邻节点与连接线、父级阶段及岗位责任，能看到“从哪里来、接着去哪里、谁交给谁”。小地图过密时只保留可辨认的角色/阶段及当前位置，不能把看不清的缩略图冒充导航。
3. 将细则、原图、表单或操作原型附着到对应节点附近展开。显示一张完整截图定位，再推近有信息的局部；讲完回到同一节点，沿原边走向下一步，或在章节/分支结束拉回总览。
4. 一次一个主焦点，路径可随口播强调，详细要求逐项讲；其余结构稳定可辨。先显示结构骨架不等于提前泄露练习答案，也不要求将未来全部细则挤在全景。
5. 路径线不得穿字，箭头落到正确目标；高亮同时交代当前对象及所用关系。实测进入、推近、局部读图、归回、跨段衔接的连续编码片段。

图中的边必须区分 `sequence`（先后）、`handoff`（交接）、`contains`（包含）、`parallel`（并列）、`condition`（条件）、`field_link`（字段关联）。并列材料不能画成必须逐一审批的串行步骤；条件性支持事项不能画成所有业务的必经节点。原图有歧义时按有效口径处理并保留追溯，不能擅自创造业务顺序。

## 员工小人演绎

按当前项目配置复用已确认人物（酷果配置单独加载），不另创不一致的角色。适合演绎：拍摄商品与消费者同框、核对SN、整理单据、递交跨泳道材料、收到退回后补充并重提。人物的动作改变对象状态或揭示角色责任；人物与实际照片/截图配合，既说明动作又让学员看懂真实合格样例。人物不能遮脸、遮关键字段、遮连线，也不靠循环走路、点头、漂浮来凑运动率。

## 原图完整性：文字提取之外再盘点图片

先渲染并逐页查看原件，再抽取每张有独立教学信息的图，不能仅依赖PDF文本/OCR。图内蓝字、角标、印章、水印、字段和示例的组合关系都可能是来源规则。保留页码、区域、原始或无损提取资产及SHA256；裁图保留原图上下文，不裁掉必要标题、批注、字段或地域差异说明。

`source_images.json`逐页登记，即使某页无图也要记录。图片优先纳入对应分镜：

- `instructional`：流程原图、表单样本、票据、实拍、截图、含规则的图内标注，必须有使用去向。
- `decorative` / `blank`：无教学信息才允许排除，并写清理由。
- `duplicate`：没有新增信息的重复图，可指向已使用的同一图；新增标注/不同结果/不同字段不能算重复。

“已用文字解释”“有同类图标”“版面放不下”“课时太长”“OCR未提取到”均不是信息图的排除理由。空间不足改成全貌定位→局部放大→回到节点，或增加必要读图时间。保留图的辨识价值，而非仅在角落放一张不可读缩略图。确有无法使用的资料问题登记为未解决项，不标为已覆盖。

正文将原图中的操作/证据要求与讲解对齐，高亮看哪里、怎样判断，不读完所有无关示例数据。地域或格式例外跟随相关示例出现，不能把样本当作所有地区统一格式。隐私处理使用派生副本并保留教学字段含义，不把处理后模糊区域当成可读证据。

## 可检查的数据契约

新建/重做工程在 `project.json`设置`content_contract_version: 2`；模板的`process_visual_default`记录按内容选择表现形式的策略，不代表已经完成绘图或验收。历史冻结项目不自动迁移。

`knowledge_maps.json`：`{"maps": [...]}`，每张地图记录：

- `id / canvas_id / diagram_type`：图类型为flowchart、swimlane、relationship、tree、prototype或comparison。
- `nodes: [{id,label}]`，`edges: [{from,to,type,label}]`。边类型见上；label解释该关系，不能空。节点位置及边路由在实际绘图源码保存并保持稳定。
- `overview_scene_id / return_scene_ids`：分别绑定总览和归回/回顾镜头。

仅地图分镜设置`map_mode: true`并增加`unit_id / map_id / map_node_ids / view_mode`；`source_image_ids / character_action`适用于其他形式。`view_mode`为overview/local/return，同一业务单元共用地图和画布；局部实物或屏幕特写仍绑定原节点。任何内容在未选择地图模式时均可不填地图；不能仅因内容属于流程、交接或层级就强制地图。

`source_images.json`：`{review_status,page_reviews,images}`。`review_status`为reviewed才表示逐页盘点完成；每页记录`{page,image_ids,note}`，无图页以空数组和说明登记。每图记录`{id,source_page,source_region,kind,information_value,decision,exclusion_reason,duplicate_of,asset_path,sha256,scene_ids}`。include图的文件和哈希必须真实，scene_ids与分镜source_image_ids双向一致。模板初始pending/空数组不代表已完成。

`scripts/check_course_completeness.py PROJECT --stage script|storyboard`在script阶段核对完整课末句；storyboard阶段增加地图及图片台账检查。`validate.py`自动调用。其通过只能证明填写、文件及关联完整，不能证明图谱语义正确、所有原图已被发现、成片确实使用或看得清。

## 最终审片的三个补充证据

- **关系可见**：从实际MP4连续看“总览→局部→归回/下一环”，无字幕也能识别先后、包含、责任或条件。单独几张静帧、很多不同canvas_id或大量图标不算证据。
- **原图可用**：逐页原件与图片台账对照，再按scene_ids在实际MP4查全貌、重要局部、对应旁白及阅读时间；台账无遗漏不等于成片无遗漏。
- **结尾确实说完**：最后教学内容后，以同一音色完整说“本节课程到此结束，感谢大家观看”，字幕一致；核对最后一段实际音频/转写与正常速度听看记录，检查尾字、片尾配乐遮盖及声音后余量。仅文稿匹配不能标记音频通过。

## 本次国补课程的具体教训

1. 原件已有多角色流程总图，拆成许多小镜头仍会丢掉职责与先后关系。“分镜很多、都标continuous”不等于一张连续大地图。
2. 原件第9页实拍中的彩色注释包含确认单/地址、提货合照中的员工、商品与消费者等要求；只读正文会遗漏。补旁白或示意图后，实际照片仍有辨识与模仿价值，不能随之省略。
3. 表单、票据、包装SN/串号与激活页面等实图，应与原有操作截图一样纳入清单。图标能概括类别，却不能教会学员识别实际样本。
4. 收尾总结和品牌片尾不能代替口头结束语。固定末句在锁稿时加入，避免渲染完成后才发现没有录音。
5. 技术探测、解码、规则覆盖与字段检查没有发现上述教学缺陷；保持四层QA，新增关系/图片/收尾的实际成片证据。运动率不足时补真实教学动作，不能靠无意义运动或“培训需要静止”的理由掩盖结构缺失。
6. 图片和人物放进画面后仍须查后绘说明条：标签的完整字形高度也要预留，避免只露上半行或人物只露头。正文文字框互不交叠，不能替代图片实际显示区、图片标签、人物全身与后绘实色板的检查；在最终MP4复核并用已知遮挡作负向对照。

## 选择关系地图之后的连续性

画面按内容选择，地图可覆盖局部业务单元，多个场景可采用不同画布；不要求整课固定世界坐标、唯一canvas或一条相机轨迹。只有已经选择地图的连续段，才保持节点身份、连接语义和段内空间连续。以下是地图实现方法，不构成选地图的前置要求。

- 长距离旅行分为“在原节点原地拉开 → 在较宽视野沿路线平移 → 推近目的节点”，避免同时在高倍率平移和缩放时穿过空白，或跨越太远形成闪跳。总结与练习回访也遵守此规则。
- 相近口播锚点若只间隔约一两秒，先把这组关系一起留在较宽视野，改变强调即可，不机械逐词快速推拉。镜头落定时测当前文字完整性；画面边缘的相邻对象有意延续到画外，与当前焦点文字被截断分别处理。
- 语义缩放可减少总览细则，但节点位置不变，层级形状和字号应平滑插值，不能在某一倍率突变成另一页。未来细则按口播展开，主路径、阶段与角色先保持可辨。
- 多条票据要求共用一张原图时，完整样例保留一次，后续用固定附着的同源字段局部及映射线解释；不把同一完整截图反复铺成一排。全部信息图的全貌仍要有真实展示时长和成片去向。
- 互斥结果不能画成串行：通过通向补票据，不通过通向修改；修改返回原录入／核验环节。退货、数据查询是条件支路，不是每笔正常交易的必经步骤。并列材料用包含或并列，不暗示逐件审批。
- 对采用地图的连续段记录其canvas_id、节点坐标和相机关键帧，检查该段内衔接连续性、最大逐帧位移和倒序seek。再看覆盖“局部读图 → 拉开 → 跨阶段交接 → 推近下一节点”的连续编码片段；结构字段、静帧与技术解码不能代替这项观看。

历史国补课程当时冻结声音和字幕、仅重做视觉；该任务边界不自动套用新课。连续性证据必须绑定当前渲染源码及最终视频哈希。原图内部小字的可读性、机器几何扫描和人工全片听审分别记录，不混称全部通过。

业务大地图还须区分“讲课访问顺序”和“实际办理顺序”。不能把每段课题依次连成业务箭头：例如先讲票据与照片要求、后演示登录收银端，不等于交易要先开票再进入系统。主线按原件业务流程连接；材料、照片、字段校验放在对应主节点旁作包含或映射支路。讲课镜头可先访问这些要求，再回访操作主线，但不改变真实先后。语义缩放后须重新计算连线端口到可见节点边界，避免箭头被放大的节点底板盖住；进入节点的路线同时避开挂在该处的练习、人物和原图。

品类差异也要画成分支：按品类采集的地址、识别码等，不能画成所有品类都依次填写。退回路径要回到能处理该类材料的入口；不能为画图方便把所有失败都指向OCR或某一个编号字段。把这些条件写成来源支持的图谱回归项，再在实际编码图中核对箭头和所属节点；只有字段台账通过仍不够。

字幕安全区回归：本次镜头从银行流水平移到推荐汇总表时，已讲过的相邻说明“新注册企业／历史银行流水”仍在画面中，下行却被字幕实底带遮住。局部焦点切换不能让相邻有效说明退出审计；成组说明整体上移或调整局部取景，保留完整字形及与字幕带的间距，在实际编码画面复查。详见[完整图形遮挡检查](14-semantic-layout-qa.md)。
