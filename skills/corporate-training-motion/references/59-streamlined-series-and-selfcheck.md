# 7.0.0 精简高效工作流、多集系列课、代码化动画与自查验收

本规范由用户于 2026-11-23 明确授权升级，面向标准 Agent Skill 宿主（Antigravity / Claude Code / Codex / Cursor / Windsurf / WorkBuddy / Trae 等纯对话与 CLI 流程，无独立插件依赖），目标是：**降低用户人工把关负担、去掉形式主义冗余、释放代码化动画表现力、提高一次达标率，并支持灵活回改。**

## 1. 多集系列课统一批次模式（1 门课多支视频 + 配套文档）

当一门课程包含多支章节视频（及配套讲义精要、章节测验题库、可打印手写作业等）时，**整门课作为一个统一批次推进，不为每支视频重复跑全套重流程**：

1. **统一大纲与讲法**：一次性规划全部章节的视频、讲义、测验与课后闭环作业分工，用户一次确认。
2. **统一逐字稿**：按章节编号（如 01–06）组织完整口播稿与原件要点覆盖对照，制作端自查修精后一次交付用户确认。
3. **内容母版三选一 + 全课精简分镜**：不再要求每个教学片段都写 3 套备选方案。改为按本课内容类型提炼核心视觉母版（例如认知模型类、七环节对照类、管理带练类、数据热力图类、短案例暂停互动类、专项服务情景类），**每类母版提供 3 套实质不同方案**供用户定调；定调后全课逐段直接输出 **1 套最优导演分镜**（写入 `storyboard.json` 的 `template_masters` + `segments[].template_id`）。
4. **全课抽 3 段代表性有声小样**：跨章节分层抽取 3 段覆盖不同母版与高风险实现的完整有声小样（带真实片头/正文/片尾接缝及多角色配音），经用户确认后锁定共用视觉、声音、字幕与包装规范。
5. **共享母版、分集独立导出**：共享同一套配色、字体、进度条、音色与片头片尾，按章节分别导出独立 `01_xxx.mp4`…`06_xxx.mp4`（各自配独立 `.srt` 字幕与课程封面），并与配套《讲义精要》、测验题库、A4 可打印手写作业一并交付至 `桌面 `ai 制课/<课程名称>/``。

## 2. 代码化自由动画表现（不调生图、不用静态贴图）

- **底线要求**：坚持**代码驱动的动态呈现**，**不调用外部 AI 生图，不用任何整张静态 PNG 人物贴图（旧版 `C01..C03` / `M1-repaired` / `blue-cast` / `retail-v1` 静态人物与旧版 `acting.js` 细长模型已从 Skill 彻底移除，严禁复用或重绘类似旧风格）**，产品范围仍限定 Apple 及明确适配 Apple 的无他牌配件。
- **唯一人物引擎 `CourseActorsCute`（3.3 头身简洁可爱多部件矢量人物）**：所有人物演绎**必须直接加载并调用随包 `workbench/motion/actors_v3_cute.js`（`window.CourseActorsCute`，含 3.3 头身可爱比例、不滑步世界坐标落地步态、方案 B 迈步平滑转侧身与停步回正、防弹膝 2-Bone IK、亮晶晶豆豆眼/蜜桃腮红与原版 KG 胸标）**；如需新增顾客外貌，只能在同一套 `actors_v3_cute.js` 骨架内按场景扩充发型与便装（且服装配色不得与背景墙面/地面顺色），严禁退回旧版 `acting.js` 或生成静态 PNG 人物！
- **D+B 融合动画范式（彻底告别静态 PPT 感）**：
  - **场景与镜头（路线 D）**：全屏纵深门店场景（无大白框 PPT 壳）+ 虚拟摄影机推拉跟拍（Zoom/Pan）+ 人物真实迈步进场/互动/后退/离场 + 形变转场 + 直观的视觉隐喻动画（如水平基准线对比、焦虑仪表、星芒粒子）。
  - **漫画情绪与弹幕（路线 B）**：对话与痛点处自然融入飞向受众的漫画弹幕卡片、冷汗/`?!`/后退速度线/冷风线条与荧光笔公式强调，并始终保留画面底部专属课程进度条。
- **1-Beat-1-Visual 意象对位与防吞字同步**：在分镜阶段先把口播拆成**最小视觉意群短句（每条 2.5–5 秒、一般 ≤ 26 字，保持完整语义短句避免尾字 EOS 截断）**，逐条写清“这句口播对应什么视觉意象/动作变化”与“同屏极简锚点字（建议 ≤ 35 字）”；再交由 `scripts/tts_sync.py` 调用本地 `scripts/qwen3_tts.py` 合成音频并用 `check_tail_energy()` 校验尾音完整（绝不采用按字数均分长句冒充词级时间戳）。
- **去 PPT 化与禁止伪动态**：严禁把整段说明文字塞进白框卡片当 PPT 读，也严禁把多条长口播塞进同一页大卡片并用 `Math.floor(t / N)` 定时轮流亮框或 `Math.sin` 假波形充当“3.5 秒内有变化”。每次视觉推进必须体现**镜头切换、视觉隐喻演变、对象状态变化或人物真实动作**，可直接复用 `workbench/motion/visual_metaphors.js` 中的轻量 Canvas 意象原语。
- **角色与构图底线保留**：黑衣 KG 店长、蓝衣店员、黑衣 MyCoach、便装无标顾客；人物通过发型与穿搭清晰区分；同场对白朝向受话人、柜台前后遮挡合理、脚底与物件有真实支撑、文字与字幕不重叠遮挡。

## 3. 精选明亮通透浅色画布色板

- 新课默认随机抽取色板，但**随机池严格限定在 `workbench/course-palettes.json` 中 `random_eligible: true` 的 16 套精选明亮、通透、高对比（WCAG ≥ 4.5）、无绿色的浅色系色板**（涵盖晴雪银红、温瓷靛蓝、冰川海蓝、亚麻深咖、樱雾青灰、云影琥珀、象牙赤陶、霜雪鸢尾等 16 种差异化明亮气质）。
- 压抑/深色画布（如午夜蓝、炭灰）标记为 `random_eligible: false`，仅在用户主动明确要求深色风时才启用；同一门课视频画布与配套讲义/作业保持视觉和谐。

## 4. 取消强制独立盲审与形式化监督，整合为“产出前实质自查验收（Self-Check Gate）”

为避免多轮子 Agent 盲审与繁复回执链消耗额度和时间、增加用户负担，**取消强制的独立盲审子 Agent 与形式化监督侦探**，整合为制作端在交付用户前必须自己扎扎实实做完的**实质质量自查清单**（把能自己发现和修好的问题全部修完，达到高精良度再交用户看）：

- **大纲 / 逐字稿交用户前自查**：
  1. 逐项核对用户全部显性要求与禁忌词（如去敏、匿名店名、无自报内部部门、保留酷果星创开场问候语、完整收尾）。
  2. 原件关键业务要点、条件与例外有清晰去处与取舍台账，不漏核心事实、不编造未确认的指标/金额。
  3. 逐句通读：像真人在跟受众面对面讲工作，短句自然、无“资料提到/原件显示”等旁观口吻、无同义车轱辘话、无依赖未发原件的悬空指代；**不把用户的制作限制或避坑叮嘱当成口播写进正文**（如“大家对七步法很熟，这节不讲基础步骤 / 隐去店名 / 不讲后台按键”等过度纠错元说明，制作端心里执行即可，不念给学员听）。
- **分镜 / 三段有声小样交用户前自查**：
  1. 多集/多段视觉骨架有节奏变化，不连续套同一张卡片；每句口播有对应的信息或动作推进。
  2. **品牌片头/片尾与原版 Logo 硬规范**：
     - 酷果片头/片尾**必须调用随包 `scripts/bookends.py`（基于批准 R5/R8 Blender 渲染母版与 `title-tracking.json` 精确时序，片头标题严格在 `3.72s–4.34s` 三维背景白底落定后浮现）或直接使用 `assets/bookends/blender/*.blend` 经本机 Blender 渲染**；严禁自行用估算秒数在三维片头动画中途硬叠文字框盖住片头动画！
     - 酷果课程的封面、正文顶栏与结尾一屏要点总结卡**必须实际载入随包原版透明 Logo（`assets/brand/kgxc-logo.png`，按可见边界等比缩放，不拉伸不变形）**，禁止只写纯文字品牌名替代 Logo。
  3. **音画精准同步与去 PPT 化铁律（1-Beat-1-Visual，杜绝合并长句与光标亮起）**：
     - 凡包含多个画面切换点、公式、数据柱、1/2/3/4 编号或对比动作的讲解，**严禁合并成一条长音频后用硬编码秒数猜测触发动画，严禁多句共用一张综合卡片并用定时光标轮流亮起充当动态，也严禁在整句起始 `dt=0` 提前剧透后半句才讲到的卡片、红叉或结论**！
     - 必须在 TTS 合成阶段按**最小视觉意群短句（每条 2.5–5 秒、一般 ≤ 26 字，每个新视觉意象对应 1 条独立短音频）**驱动镜切换与元素演变；口播说完整句，屏幕只留极简锚点词（同屏正文建议 ≤ 35 字，严禁 20 字以上说明长句堆满卡片），确保“口播没念到，画面不抢跑；口播一念到，意象画面同步演出来”。
  4. **画面动态节奏红线（杜绝长时间静帧疲劳与伪动态）**：
     - 任何正文画面**禁止静止停留或仅靠边框变色停留超过 3.5 秒而无新的视觉信息、对象状态变化、空间镜头推进或人物动作**；开场问候页若口播超过 4 秒，必须按意群分步展开（原版 Logo 与问候 → 课题聚焦 → 核心痛点/思维对比 → 本节看点逐条呈现）。
  5. **对话气泡锚点与实时同步硬规范**：
     - 对话气泡的指向箭头**必须根据当前讲话人的真实画布坐标（`speakerX, speakerHeadY`）动态计算指向说话人头部/嘴部**，禁止写死固定偏移指向空气；
     - 气泡文字必须**随当前角色正在说的子句实时切换**（或与当前子句完全一致），绝不允许角色刚说第一句迎宾语时，上方气泡已提前剧透最后一句话。
  6. 多角色对话启用本地清晰分声（如旁白男声 `didi` + 顾客/员工/店长男女分声），先实测短句自然度，再对齐真实音轨锁字幕、动作、编号顺序（1/2/3 与口播严格同步）及花字/原库音效（`teaching-native-v1`）。
  7. 实际查看渲染关键帧与编码结果：查片头标题出现时机、原版 Logo、人物朝向与支撑、气泡箭头指向、口播词句与画面对应、文字安全区与避让、封面仅首帧、末句完整无残音。
- **完整成片交付前自查**：
  1. 按每支成片核对 MP4/SRT/封面三件套完整、音画时长与非静音、片头片尾接缝、字幕错别字与换行、实际抽帧画面精良度。
  2. 视频、讲义精要、测验题与打印作业口径一致、互相呼应；过程文件默认保留在工程目录，绝不自动删除。

## 5. 支持灵活回改、只重做最小影响范围

用户在小样或成片完成后回头修改某段逐字稿、某页讲义或大纲微调，属于正常打磨，**绝不因此强制把大纲、逐字稿、分镜、小样全部重审重走一遍**：

- **仅修改局部台词/画面/花字/音效时**，锁定受影响章节与片段，只重配受影响句子、重渲染对应片段与衔接、更新对应字幕与受影响讲义条目。
- 未变更章节的配音、画面与已确认视觉/声音规范全部复用，做完局部自查验收即可直接交付更新版。

## 6. 移除网页工作台 UI（纯无头渲染后端 + 对话驱动）

- 由于全部构思、改稿与视频微调均通过对话、结构化提问和独立审阅成品（HTML / MP4）完成，**已全面移除 `design.html` / `design.js` / `design.css` 与 `index.html` / `editor.js` / `style.css` 人类操作网页 UI**。
- 本地工作台后端 `backend.py` 仅保留无头渲染入口（`renderer.html` + `native/index.html`）与工程 API 供 `render_worker.py`、`check_workbench.py` 和 `workbench.py export` 调用；访问 `/` 返回精简的无头服务状态 JSON，不再渲染任何网页编辑器。
- `kgxc_course.py start / resume` 全程不自动弹出浏览器标签页。
