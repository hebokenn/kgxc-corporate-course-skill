# 01 · 制度解析与可追溯规则台账

## 字段规范
一条规则对应文档的一项可以核验的业务断言；必要时同一条款拆成不同的规则。`source_rules.json` 数组包含：
- `id`: R001 … 稳定的源规则编号；`clause` 原文编号；`page` PDF 页码；`exact_excerpt` 原文文字（不得自作修改）；`summary` 便于讲解的重述。
- `modality`: mandatory（必须/不允许/应当）、recommended（建议）、conditional（条件下执行）、descriptive（定义和事实）。
- `scope`: 适用对象、地域、时段和条件；`exceptions`: 文档明确的例外；未知时留空，而不编造。
- `importance`: critical / normal。critical 强制覆盖/或经人批准有理由省略；normal 可在大纲明确排除。
- `risk`: 对该条的误读风险；`review_status`: verified / pending；`blocking_issue`: 当 pending 时指向待确认事项；`teaching_status`: planned / covered / excluded；`exclusion_reason`: 被排除的人工理由。

## 提取与核对
1. 先按原文件章节目录建索引，**读完每页**，包括表格、注脚和例外。
2. 原文一次可含时间、对象、动作、审批、后果，视教学需要拆成多条，但完整引用 clause。
3. 不因无法解读而省略：把它登记为 `pending`，以原文为准进行提问。
4. 用“适用条件 → 责任人 → 必做动作 → 时间/阈值 → 例外 → 结果”检查每条规则是否有漏。
5. 任何用意、常识性建议、课程案例的推测均标 `讲解示例`，不得作为制度原文。
6. 为呈现具体时刻进行的演算必须显式标 `示例（基于假设）`，并在画面上显示条件；例如标准 C 班在 22:00 结束只能在「门店营业到22:00」条件下成立。

## 图片也是规则来源

逐页渲染查看并建立`source_images.json`，记录图内注释、样例字段、流程连线和实拍条件；纯文本提取不能代表读完原件。对所有有教学价值的图片安排分镜，全貌定位后按需放大；只有无新增信息的装饰、空白或重复可说明理由后排除。图与规则分别核对，补讲规则不等于已经使用原图。字段与检查见[可选关系图与原图保留](18-relationship-maps-and-source-images.md)。

## 高风险类别
- 数字或范围，如 30 分钟、40–44 小时、186 小时、次月2号；
- 阶段的先后，如审核通过后上传；
- 模态强度，如建议排班与强制排班；
- 例外条件，如商场另行要求、街铺专门通知、节假日、总部确认；
- 人员权限，如店长、区域销售经理、代班店长、Coach 培训师、储备 Coach。

## 问题处理
`open_questions.md` 按 `Q001 / 条款 / 原文 / 疑义 / 影响模块 / 需要谁确认 / 状态 / 决议` 登记。
有阻断问题的模块不能发最终成片；如果在时间压力下只能制作其他模块，必须在交付说明写清覆盖范围与未制作段落。
