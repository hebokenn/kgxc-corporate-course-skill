# 渲染与声音时间轴

默认新课先建立含工作台的工程（scaffold），再执行：原始资料 → 规则台账 → 批准稿 → 分镜与教学事件 → 连续录音 → 真实对齐 → 确定性画面 → 编码/混音/字幕 → 最终MP4与工作台恢复复验。规则与稿件决定内容，渲染器只实现已确认数据。

使用既有实际引擎：排班课程为HTML/Canvas+Playwright逐帧PNG+FFmpeg；Remotion起始示例仅为可选原型；本包内置网页与插画引擎，或按内容选择Blender。内部工具路径见[调用表](25-internal-tools.md)。选择与依赖记入project.json/导演单，不同时维护两套主渲染器，不把只读过接口写成渲染兼容。

所有状态从绝对时间计算；等待字体、图像和脚本ready后采帧。随机数用固定种子。每个进程使用work/内独立silent/pending，互斥锁阻止同时写入；完整编码和全量解码成功后原子提交delivery/。并行读取不得验证尚在写的候选；失败清理仅清自己的工作文件。

声音与画面时长按真实时间轴，尾部补稳定阅读帧；不以-shortest截断口播。文字区间端点、数值和比例保持真实，揭示区域或焦点可以运动，批准数字不可滚动成错误中间值。声音处理保存原带、采样映射、混音参数和哈希。

目录唯一规范见[15-workspace.md](15-workspace.md)。QA、发行文件与工程路径相互引用时用课程相对路径。包内包含完整再制作所需声音和素材，不依赖历史版本或开发机绝对路径；运行环境、系统字体、可选本地Whisper模型单独记录。

最后ffprobe核对编码/尺寸/帧率/音轨/时长，ffmpeg -v error -xerror -i FINAL.mp4 -f null -全量解码；抽查实际编码帧，与同帧源场景对照；声音试听及正常速度观看另行记证。脚本成功、原型通过和用户验收分别记录。

## 真实包装时长与本地字幕能力

导入片头、片尾时先用ffprobe读取实际帧数和时长，再锁声音偏移及正文起点。品牌生成器可能为长标题/副标题自动延长；“最少14秒/8秒”或配置目标值不是实际值。逐段核对包装、正文、片尾帧数与时间轴一致，不能只检查总时长，也不能靠截断最终总帧数掩盖正文整体错位。若需指定时长，可在保持课程标题的前提下缩短品牌副标题后重合成，并重新测量；不要剪断已说出的内容。

开工前探测FFmpeg实际滤镜，不能只凭已安装ffmpeg就假定含libass/subtitles。缺失时可在本地用授权中文字体将冻结字幕逐帧叠到已有无声视频，再合入原音轨；不为字幕故障重发云配音。管道解码、合成与编码使用一致的帧预算，显式等待解码器和编码器全部正常退出，再独立探测与完整解码并原子提交。最后从实际MP4比较各段源帧，检查包装偏移、单行字幕字形及AAC音轨对应。

如果系统默认FFmpeg精简版缺少字幕滤镜，而本机已安装ffmpeg-full，优先在课程脚本中明确选用经滤镜探测通过的完整二进制（macOS Homebrew常见路径为`/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`），保留可覆盖的`FFMPEG`参数和通用回退。不要因keg-only未链接而重复安装，也不擅自改全局链接或重做已生成的旁白。切换字幕渲染器后，从实际编码帧复查中文字体、单行字幕安全区和练习答案揭示时刻；旧渲染器的验收不自动覆盖新输出。

本地播放器若支持章节/拖动，预览服务必须正确返回视频字节Range（206与Content-Range）；仅能加载元数据、显示总时长不证明可跳转。验证首段、中后段实际currentTime与选择值一致，seekable覆盖整片，另核对范围读取的字节内容及越界416。普通SimpleHTTPRequestHandler可能只给200整文件，导致能显示时长但跳转回0；修服务即可，不重做视频或声音。

暂停/续做及局部重渲后，给完成的无声正文单独保存“视频哈希→已审计源码哈希”的绑定，合成前同时核对。仅确认工作区源码通过检查、旧body.mp4帧数正确，不能证明旧正文来自新源码。中断时保留旧交付与pending边界；续做应先完成渲染再绑定来源，禁止把半成品或旧缓存按新时间轴直接合成。

源帧与编码帧先在相同原生分辨率、相同裁切区域对照，再生成缩略图供审阅。浏览器Canvas和FFmpeg分别缩小图片时，重采样、JPEG及YUV/RGB转换会额外放大细线边缘差异；不能把缩略图均差直接当作镜头不一致，也不能仅抬高门槛让它通过。保留原始诊断，复用经过验证的原生同帧比较，额外核对几何、文字与动作变化。

嵌套源码与旧帧：使用上游render.mjs时，先确认其pageHash覆盖范围。当前实现只追踪HTML和同目录JS/CSS；若画面源码在source/等子目录，修改后必须显式--force，或按实际递归依赖指纹删掉受影响帧，再完整编码并记录来源。不能因“渲染命令返回成功”就认定旧缓存已失效；最终MP4仍需与当前源画面的动作过程帧作比较。

## 新课的默认编辑与导出链

每门新课从scaffold开始带有工作台，制作中的字幕、画面文字、图片和实际时间轴进入workbench.json。通用画布使用scene-graph-v1；选择网页、插画或三维时接入seek-bridge-v1。原生渲染器可自由选择，但最终课程不能绕过可编辑绑定直接只交付视频。工作台画面与正式导出共用CourseRenderer。

configure只初始化尚未制作的草稿，后续修改保留已有用户编辑；预览和最终检查执行check_workbench.py --runtime。导出使用workbench.py export或工作台按钮，记录文档、源码/媒体与视频哈希。工程包必须包含当前源码、实际audio/assets及独立启动器，并实测解压重开。命令与接口见[27号工作台契约](27-content-workbench.md)。
