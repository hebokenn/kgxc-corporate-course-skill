# 文字边界与门店胸标

高亮框不能由旁边的手写坐标独立决定宽度。已发生的错误是框宽570，而文字行延伸到框外，右边线穿过“资格待核实”；连续两个焦点窗口也曾同时显示。对文书使用 `document.data.rowFocus`，按实际行绑定，窗口默认在下一焦点开始时结束。

```json
{
  "rows": [["教育优惠", "资格待核实"], ["以旧换新 / 分期", "按具体条件确认"]],
  "rowFrames": [594, 625],
  "rowFocus": [
    {"row": 0, "atFrame": 594, "endFrame": 625},
    {"row": 1, "atFrame": 625, "endFrame": 653}
  ]
}
```

工厂从同一行的版面范围生成带留白的边框，行文字设置 `nonOverlappingTextIds`，高亮设置 `enclosesTextIds`。编译后的普通节点保留这些关系。configure 自动为含约束的工程启用 layoutPolicy。普通图形也可声明这两个字段，引用具体的真实文字 ID，不能引用一个空占位对象。

同一预览和导出引擎在字体加载后用 Canvas measureText 取得实际字形范围，叠加当前定位、缩放、编辑位移和矩阵后，在标注自身坐标中检查：边框需包住目标文字并留出描边空间，同一行左右文字应保有间隔。边线进入文字、字段移到框外、改字后列重叠，都会在对应帧报错并阻止导出；导出回执的 layoutAudit 记录检查过的渲染状态和规则。不能只验证终帧，当前行高亮的出现、保持、消失及下一行接替都要检查。

这些检查覆盖**已声明的文字包围和同行间隔**，不是对全部像素遮挡的审美判定。人物接触、表情、字幕与画面、不同物件之间的关系仍须实际观看；不能以新检查通过声称所有重叠都已自动解决。人工改动字段后也应重新预览和导出，不复用旧回执。

## 三类角色与必需胸标

- 店长：黑衣、原版 KG，M1。
- 店员：蓝衣、原版 KG，S01 女性 / S02 男性，各自使用自己的取景和胸口坐标。
- Coach：黑衣、MyCoach，COACH，保持其自己的 MyCoach 原图，不能加 KG。

```sh
python3 SKILL_DIR/scripts/course_tools.py stage-company-character COURSE --identity S01 --out COURSE/project/source/staff-female.json
```

输出包含原角色与胸标 assets、角色 data、身份和标识。把 assets 合并到构图并使用 data 生成 actor，不直接拿不带标记的 blue-cast.png 裁切当交付。原图保留，胸标是可编辑的独立原始图层，与人物缩放/半身取景一同变化。M1、S01、S02 缺少胸标绑定会拒绝生成；COACH 使用自己的 MyCoach 字样，不能用通用 KG 入口覆盖。

检查实际全身、半身与动作，既检查“是否有 logo”，也检查放置位置、尺寸、标识是否对应角色。新衣服或新姿态须重新核对自己的胸口标定，不能照搬其他角色的坐标。
