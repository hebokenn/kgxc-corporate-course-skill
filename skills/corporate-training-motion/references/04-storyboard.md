# 04 · 分镜契约与口播对位

## 数据契约
`script_segments.json`: `[{id,section,text,rule_ids,estimate_sec,tag}]`。`tag` 可为 intro / training / recap；非 intro / recap 必须绑定至少一条规则。

`storyboard.json`: `[{id,section,narration_ids,duration_sec,visual_type,headline,rule_ids,on_screen_facts,animation_cues,layout_notes}]`。
- `on_screen_facts`: `[{text,rule_id}]`，事实对应到规则；背景标签可不写在此字段。
- `animation_cues`: `[{at_sec,action,target,narration_anchor}]`，0≤at_sec≤duration_sec；`narration_anchor` 为口播原句里的锚定词。仅估算阶段允许留空，但正式渲染必须与录音时间轴重新对齐。
- `visual_type` 必须来自 `03-visual.md` 组件词表或 `ChapterIntro`。

## 导演分镜契约 2

新建或重做视觉在project.json设置`visual_plan_version: 2`，并在每段分镜增加：

| 字段 | 要写清的内容 |
|---|---|
| `knowledge_relation` | process / hierarchy / handoff / condition / comparison / field_linkage / definition / recap |
| `learning_goal` | 观众看完这一段能理解或判断什么 |
| `visual_action` | 哪个对象从何处到何处、哪种关系被建立或改变；不能只写文字淡入 |
| `visual_strategy` | diagram / demonstration / object_action / comparison / source_diagram；title_only和text_cards不允许 |
| `canvas_id`、`focus_object_ids` | 稳定画布与对象ID；连续段不换ID或随意重排空间 |
| `canvas_mode`、`visual_choice_reason` | continuous和separate均可，按内容选择；用同一字段说明选择理由，不默认地图 |
| `camera_plan`、`camera_reason` | 镜头起止/路线、移动时机、停点与理解收益；保持静止也要有理由 |
| `local_expansion` | 什么信息在原位置附近展开，和父节点怎样相连 |
| `return_to_global` | 仅地图/关系图需要；其他场景可省略，用camera_plan说明实际交接 |

先做知识关系判断再填镜头，不从“每段一页”的模板反推内容。`scripts/check_visual_plan.py`仅验证契约；即使字段齐全，只有标题和文字卡片的实际画面仍不得通过导演视觉审阅。

G2证据：`qa/visual-evidence.json`记录关键帧、连续动态小样及哈希，复核spatial_continuity、diagram_expression、reading_time、occlusion四项并注明检查区间与方法。动态小样须包含进入、展开、读图、退出/归回的连续过程；不能用静帧拼接视频或互不连续的截图代替。未有真实声音的设计稿保留estimated标识，不冒称实测同步。

## 画面与讲解逐点对位

分镜为每个可见业务点记录 `explanation_bindings`：`[{on_screen_text,narration_id,narration_anchor,explanation_scope,timing_basis}]`。`explanation_scope`写明本段说明了什么，`timing_basis`为estimated或measured；正式有声版本补实际出现及讲解时间。导航角色名、节点标题与已讲背景可保留，但新增业务条件、数值或要求不能以“背景”名义跳过讲解。

- 讲解须说明足以理解该点的含义、适用条件或操作；仅重复标题、列出名词、或在字幕上复印同一句提示不算解释清楚。
- 双向核对：原稿应讲内容是否可理解；实际画面每个业务点是否有本段对应讲解。跨段有原稿、规则ID匹配和字幕存在，都不能代替局部教学闭环。
- “同上”“见前述”“按规定”等引用须指向学员已听懂、能定位的具体依据；条件不同或依据不清时不得照搬。不能擅自补例子、阈值或审批口径以补齐解释。
- 发现孤立提示，优先隐藏/移除，保留既有逐字稿，在正式讲到该点时同步展开；如确需补讲，按现有稿件修订流程处理。无声视觉小样只展示当前解释轨能讲清的业务点；最终有声版本仍需对照真实旁白听看。
- 回归案例：画面“取整方向：向上”，本段却只讲DG两项价格同步下调，必须退回；删去该提示，或在实际讲解取整要求的段落同步展示，才可继续验收。另一段逐字稿已经包含取整，不代表当前片段讲过。

## 可选关系图与原图契约

新建/重做工程设置`content_contract_version: 2`，逐页建立`source_images.json`，保留有教学价值的原图。只有采用地图模式时才建立实际`knowledge_maps.json`；无地图时保留空maps即可，process、handoff等内容关系本身不触发地图要求。地图分镜显式设置`map_mode: true`并绑定节点；独立图表、日历、实物和操作截图可直接表达同类关系，见[关系图与原图](18-relationship-maps-and-source-images.md)。

## 单镜内部节奏
**结构先出现 → 当前焦点出现 → 建立关系 → 留白让人读 → 再推进下一步**。
流程可在同一个持续镜头内累计 20–35 秒，节点逐条展开；这不是 PPT 翻页，镜头保持稳定、信息在推进。

## 音频绑定
1. 先最终确认讲稿，使用已授权 TTS 或真人口播生成完整音频；不能以未合成的粗略时长假装完成精确同步。
2. 保存每段的真实音频路径、准确毫秒或帧级起止、语句/字词时间轴。没有词级时间戳时，用人工语句锚点或强制对齐工具复核。
3. 每个 cue 指向特定的语音词或句末停顿，而不是简单均分到时长。
4. 图中所有关键数据出现和说出时间近似一致；声音结束后仍给用户足够阅读时间。
5. 垃圾时间不可用无意义浮动补，宁可维持稳定的图表。
6. 原文没有提供的配音/品牌资产必须征询使用授权，网络 TTS 默认关闭。

## 估算与实测分离
每个 cue 可追加 `narration_id/anchor_occurrence/anchor_source`；重复词指定第几次，anchor_source为estimated/measured。正式生产只能用实测/人工复核时间。阅读停留从最后一项落定计算；重点数字和条件固定，不用数字滚动误导。

## 观众阅读顺序与层级

编号是观众的阅读路径。同一组主项按01→02→03→04推进；一个主项的小点展开期间，父项编号、位置和当前状态保持稳定。不得因旁白再次提到“组合”等词，就把后续主项的应用画成返回较早编号。确需回顾时，先明确归回总览，再显示“回顾某项”；讲稿与编号无法一致时，先修订分镜或提交讲稿调整，不能悄悄改写业务含义。

每个有业务意义的要点都需绑定原稿锚定词及对应高亮。并列目的、限制、条件或例子逐项检查，不能只高亮第一个便跳走。未讲内容只保留导航位置/标题；已经展开的正文必须得到讲解或明确标成已讲背景。

大点与小点保持可见关系：保留父级导航或连接显示归属，前一重点保留有用业务内容供理解和对照。层级关系可在同一画面中连续呈现，不必为每个小点另出回收页，也不以“已讲完”替代知识摘要。课程目录在同一画面中按顺序讲解后自然承接第一课，不额外制作供审核用的完成总览页；进入第一课时通过课题与具体内容交代承接。

连续帧可记录 `reading_scope/parent_id/point_number/reading_phase/highlight_targets/visible_points/explained_points`，reading_phase为overview、enter、detail、return。回收帧通常是句末停留或转折动作，不新增口播；同一句内的子点仍须在动画前核验实际词内时点。帧数不代表镜头数，不用频繁切页代替连续展开。

短语连续讲解时优先保留一个稳定画布，仅转移局部焦点；不要为每个关键词替换整块文字或插入短于阅读需要的展开/收回页。阅读时间从文字清晰落定开始计算。动效对应内容关系：对照可用两侧比较，人员配合可用组合连接，流程可用焦点沿路径移动，时间要求可用区间推进；不把同一红色描框或划线重复套在所有知识点上。

父项持续高亮由稳定对象ID和上一状态决定，不能随每个子点的入场时间重新从灰色变红。转场保留原图形承接位置时，旧文字先退出，避免新旧段落在同一区域叠字；归回动作同样检查。

逐帧渲染缓存必须考虑实际动作窗口、句中关键词和字幕切换。不能假定一句话只有前几秒有动画，否则句末关键词的高亮和过渡会被缓存成静帧。验证时从实际导出的MP4抽帧，排除字幕区域比较主体变化，不用工程预览代替成片证据。

## 连续旁白与单行无标点字幕

每时刻只显示当前一条单行字幕，不保留上一行，不使用两行滚动。长句按自然停顿和完整语块拆为连续字幕；数字符号先转成不丢含义的文字再去标点。画面章节标题、字段名和业务标注按内容保留，不能把“无标点字幕”解释为禁止标题。执行[单行字幕流程](20-single-line-subtitles.md)。

字幕切分不改变原声速度；需要更多阅读时间就调整画面停留或回到讲稿修订。问答的答案起点绑定真实口播，不提前出现在字幕或画面。逐条核对原稿重建、数字单位、实际行数、字形边界和正常速度阅读。

## 连续画布镜头交接复验

镜头的下一段起点必须接上一段**实际结束姿态**，不能接上一段配置里的默认目标。段内访问过其他角色、缩放或回全局时，显式写出归回路径，并在段边界前后采样比较相机位置与缩放；自动检查必须对不连续真正报失败，不能只记一串数值。已知问题修正后重渲受影响的连续帧，再在最终MP4中检查交接过程；落定静帧正确不代表切换过程连续。阈值按画布尺度与帧率记录，不以放宽阈值隐藏跳镜。

单行字幕在数字与单位之间不得拆成前后两条（如“一百元”不能拆成“一 / 百元”），范围、系统代号、字段名称也应保持词组完整。校验唯一文本重建一致之外，还要从最终编码画面检查分行后的语义，避免字数与阅读时长合格但阅读歧义。
