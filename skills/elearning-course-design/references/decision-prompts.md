# 主动提醒与选择

选择不是审批仪式。只问会改变内容、学习路径、素材或制作量的事项；已回答或已授权代选的不再问。

| 发现与节点 | 建议让用户决定的内容和取舍 |
|---|---|
| 原稿兼顾管理与执行；拟大纲时 | 主管版偏诊断辅导，执行版偏服务操作，双轨增加分支结构 |
| 多主题争夺课时；安排章节时 | 聚焦核心，或全保留加时，或拆系列；列出原页去向，不默默删除 |
| 旧数字/模糊口径/当前性结论；写案例前 | 注明日期作历史练习，换用户确认新数据，或仅留方法 |
| 时长与内容量矛盾；估时后 | 精简、拆模块或延长；不能靠快语速硬塞 |
| 复杂能力只有讲解；设计练习时 | 一次判断、诊断解释、实操方案；说明投入与评价成本 |
| 分支情境却只交MP4；定媒介时 | 暂停题、视频配独立练习、平台交互；说明能否记录答案 |
| 缺录屏/实操/案例；展开页面前 | 补资料、标注示意、改概念训练；不编真实界面流程 |
| 旧员工管理表述与目标脱节；筛内容时 | 改可观察工作行为、待负责人核验、另成专题；不凭私生活传闻推断工作表现 |
| 密集图表/移动/无声；写画面稿时 | 分屏简化、可放大原表、下载清单；别只问配色 |
| 进入逐字稿/交接时 | 先确认结构和讲法，逐字稿完成后确认本稿再进入制作分支；已有有效确认按范围沿用 |

每项按“定位发现→影响→推荐→2–3选项及代价→将改动什么”写。每轮聚焦1–3项，用户可自由补充；等回复时继续独立工作。

记录稳定ID和 `question/finding/options/recommended/selected/status/evidence/blocking_for`：

- `open`：仍待回答，推荐不是用户选择。
- `confirmed`：用户明确选择，记录原话或定位。
- `delegated`：在用户授权范围内代选，记录授权及理由。

`blocking_for`只描述对课件或后续制作的实际影响，不让局部未决事项暂停全项目。可选美化通常不阻止继续，关键数据不能未经核实进入正式讲解。排除或降级相关部分可继续，但要留记录。

“按推荐”只指本轮已展示推荐项；沉默不是确认。没有回答可以继续标注草稿，不自动锁定。
