# 学员上下文与资料指代检查

课程必须能脱离制作端的原始资料被理解。默认学员只收到课程成品，不拥有用户上传的 Excel、PDF、PPT、手卡或工程包；只有用户明确安排分发的材料才算学员可用材料。即使会分发附件，课程仍应交代它是什么、何时使用，不能让学员先猜文件。

## 把来源转换成讲解对象

首次提到一个表单、图表、制度或界面时，按本段需要说明：

- **对象**：学员能识别的名称。可用适合教学的简短名称，不照念上传路径、文件扩展名或“第一部分手卡”等内部命名；名称要与实际内容一致。
- **用途与场景**：谁在什么任务中使用它，用它记录、计算、判断或完成什么。
- **当前内容**：本段要看的字段、评分项、条件、数据或操作入口；把理解和完成任务必需的内容直接放进课程。

不要求每句话重复全名。对象已经在本段清楚介绍且指向唯一时，可以说“这张评估表”“这一项”；跨章节重新进入或存在多个表单时，重新点明短名称。不能只在片头闪过名称，后面默认学员一直记得。

展示表单时，可重绘相关字段或局部结构，保持名称、值和条件准确；不必硬塞整张密集原表。实际讲到某个项目时，画面应让学员看得见该项目及其归属。比如讲“守时”，要定位到面试评估的第一印象维度及对应观察点，不能只停在四项总分比例上。

“来源可追溯”与“学员能听懂”分别检查。原文件名、单元格坐标、页码、待核对备注放在制作端台账；学员口播和画面改用具体对象及教学说明。确需讲解来源差异时，先介绍两者名称、适用范围和比较内容。

## 这类句子必须逐处复核

检索或通读“表里、原表、本表、表中、资料中、附件里、文件里、上面、下面、如图、按原文”等指代。命中只是待检查线索，不能靠替换关键词或自动计数判定通过。对每处确认：

1. 此时学员是否知道指的是哪一个对象？它之前在哪里被介绍？
2. 是否说清当前为什么使用它，学员要观察、计算、填写或判断什么？
3. 完成这一步必需的字段、数值、条件和结果，是否已经在课程中解释或展示？
4. 实际口播、字幕、标题和画面是否指向同一对象？不能只有制作备注里写清楚。

信息不足时先回到逐字稿补齐，再做配音；制作阶段漏了对应画面则修正画面。素材不能公开、事实不清或分发安排会影响必做任务时，标明具体缺口并处理，不能把任务推给学员自行寻找一个不存在的附件。普通命名与讲解补充由制作端完成，不额外制造确认轮次。

## 面试评估的改写示例

首次引入可说：

> 面试时，我们用《门店面试评估表》记录应聘者的回答，并给四个维度评分。接下来先看这四项怎样合计一百分。

后续不直接说“注意表里的守时”，改为：

> 在第一印象这个维度中，先观察应聘者是否按约定时间到达；如果时间有变化，是否提前沟通。

画面同时出现“门店面试评估表 → 第一印象 → 守时观察点”，并给出正在解释的行为。讲解评分档位时，学员标题用“面试评估的评分档位”，不能仅写“原表评分档位”。这些是表达与定位示例，不是新增公司制度或另一套评分标准。

## 检查时点与边界

逐字稿交接前完成无原件通读；课件或视频制作后，再按学员实际可见的口播、字幕与画面核对。记录已检查范围和仍有歧义的对象，语义不清的部分不能标为已完成；技术结构、字幕匹配或编码检查不代表本项通过。

本规则用于后续新课及用户授权的改稿。仅更新 Skill 不自动改写已确认逐字稿、替换既有配音或重新渲染当前视频。
